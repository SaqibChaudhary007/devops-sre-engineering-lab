# Contributing

Contributions are welcome when they improve learning quality, technical accuracy, practical value or navigation.

## Core Rules

1. Do not copy tutorials or vendor documentation.
2. Add evidence for important technical claims.
3. Label version-sensitive behavior.
4. Never include credentials, client-sensitive data or confidential production details.
5. Prefer one canonical knowledge location and link to it.
6. Keep explanations beginner-accessible before adding advanced depth.
7. For labs, document environment, expected behavior, observed behavior and cleanup.
8. For interview reports, distinguish reported questions from questions created for practice.

## Before Opening a Pull Request

Explain:

- affected domain/topic
- problem being solved
- learning level
- evidence/source
- whether the change was lab-tested
- version/environment if relevant
- related labs/scenarios/interviews

## Writing Standard

Use the flow:

**What → Why → How → Failure → Troubleshooting → Production → SRE → Architecture → Teach-back**

Not every small topic needs every section, but major topics should connect to the full engineering lifecycle.
