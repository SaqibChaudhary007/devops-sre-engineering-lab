# D00-T013 Assessment Package — SRE Foundations

This package evaluates whether the learner can reason about SRE as a reliability operating model rather than as monitoring, on-call, or automation alone.

## Assessment Components

1. [Knowledge Check](knowledge-check.md)
2. [Applied SRE Scenario](applied-scenario.md)
3. [Senior / SRE / Architect Follow-Ups](interview-followups.md)
4. [Teach-Back Assessment](teach-back.md)
5. [Rubric & Remediation Guide](rubric.md)

## Recommended Order

Knowledge Check
→ Applied Scenario
→ Follow-Ups
→ Teach-Back
→ Rubric Review

## Topic Competency Guidance

Recommended minimum:

- Knowledge Check: 80%
- Applied Scenario: 75%
- Follow-Up Depth: FD-3
- Reasoning Level: at least L3
- Teach-Back: 4/5 average
- No critical misconception around SRE identity, SLI/SLO/SLA, error budgets, toil, paging, on-call, mitigation vs permanent correction, blameless learning, progressive delivery, or production readiness

## Critical Misconceptions

A learner should not leave this topic believing that:

- SRE is monitoring only
- SRE is on-call only
- SRE is identical to DevOps
- 100% reliability is the default target
- SLI, SLO, and SLA are interchangeable
- error budgets are permission to be careless
- error-budget policy is universal across organizations
- every alert should page
- toil means any work someone dislikes
- automation always improves reliability
- incident response should wait for perfect root cause before mitigation
- blameless means accountability-free
- canarying proves a release is correct
- production readiness means only functional testing
