# D00-T007 Assessment Package — DevOps Foundations

This package evaluates whether the learner can reason about DevOps as an end-to-end delivery system rather than as a collection of tools.

## Assessment Components

1. [Knowledge Check](knowledge-check.md)
2. [Applied Delivery-System Scenario](applied-scenario.md)
3. [Senior / SRE / Architect Follow-Ups](interview-followups.md)
4. [Teach-Back Assessment](teach-back.md)
5. [Rubric & Remediation Guide](rubric.md)

## Recommended Order

Knowledge Check
→ Applied Scenario
→ Follow-Ups
→ Teach-Back
→ Rubric Review

## Topic Competency Guidance

Recommended minimum:

- Knowledge Check: 80%
- Applied Scenario: 75%
- Follow-Up Depth: FD-3
- Reasoning Level: at least L3
- Teach-Back: 4/5 average
- No critical misconception around DevOps as a tool/team, CI/CD, flow, feedback, DORA metrics, toil, blameless learning, or DevOps/SRE/platform-engineering relationships

## Critical Misconceptions

A learner should not leave this topic believing that:

- DevOps is a tool
- creating a "DevOps team" automatically creates DevOps
- CI/CD means installing Jenkins or another pipeline tool
- deployment frequency alone proves maturity
- more automation is always better
- faster delivery must reduce reliability
- blameless means no accountability
- toil means any work someone dislikes
- SRE and DevOps are identical
- platform engineering replaces DevOps
