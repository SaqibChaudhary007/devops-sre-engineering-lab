# D00-T015 Assessment Package — Security Foundations

This package evaluates whether the learner can reason about security as risk management across assets, trust boundaries, identity, authorization, secrets, supply-chain trust, detection, blast radius, recovery, and production readiness.

## Assessment Components

1. [Knowledge Check](knowledge-check.md)
2. [Applied Security Scenario](applied-scenario.md)
3. [Senior / SRE / Architect Follow-Ups](interview-followups.md)
4. [Teach-Back Assessment](teach-back.md)
5. [Rubric & Remediation Guide](rubric.md)

## Recommended Order

Knowledge Check
→ Applied Scenario
→ Follow-Ups
→ Teach-Back
→ Rubric Review

## Topic Competency Guidance

Recommended minimum:

- Knowledge Check: 80%
- Applied Scenario: 75%
- Follow-Up Depth: FD-3
- Reasoning Level: at least L3
- Teach-Back: 4/5 average
- No critical misconception around authentication vs authorization, least privilege, Zero Trust, secrets, encryption, password hashing, provenance, CI/CD trust, shared responsibility, blast radius, or security vs reliability

## Critical Misconceptions

A learner should not leave this topic believing that:

- security means one firewall
- authentication automatically grants authorization
- admin access is acceptable because it is easier
- Zero Trust means "trust nobody"
- short-lived credentials are automatically safe
- secrets are ordinary configuration
- encryption replaces access control
- generic fast hashing is sufficient password storage
- defense in depth means adding random controls
- provenance automatically proves an artifact is trustworthy
- cloud providers own all security responsibilities
- security is only the security team's responsibility
- prevention makes detection/response unnecessary
- stronger security always means lower operational risk
